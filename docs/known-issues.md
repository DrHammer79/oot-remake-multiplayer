# Known issues in the newest release (0.11.2)

This is an early test release. Everything under "Works" was seen in our two-game tests: two copies of the game on one PC talking through the server, driven by the [autotest](../tools/autotest) scripts or played by hand, with the logs and screenshots of both games read afterwards. Testers play the releases on separate PCs, over a LAN and the internet. Please report what you see ([setup.md, Reporting a problem](setup.md#reporting-a-problem)); every open problem is on the [issues page](https://github.com/daurosk/oot-remake-multiplayer/issues).

**Every player needs the same release.** 0.11.0, 0.11.1 and 0.11.2 are protocol 12: a game and a server (or another game) of different protocol versions refuse each other, so a 0.10.1 game cannot join a 0.11 game. A 0.11.1 player can still join a 0.11.2 game, but the 0.11.2 fixes for bosses, doors and quest steps work only when every player has 0.11.2: update together. A 0.10.1 or newer kit offers the update when you start it. A kit from before 0.10.1 cannot: download `Update.bat` from the release page into the kit folder and double-click it. `Revert.bat` goes back to the version you had before.

**The game runs on Longshot v3.0.0-rc.4** (Team MagicBean's recompilation; its changes are being merged into [Hookshot](https://git.notrexed.dev/Hookshot/Hookshot)). There is no emulator in this release: emulator players keep the last emulator release (the early test release of 2026-11-12 on the [releases page](https://github.com/daurosk/oot-remake-multiplayer/releases)), which cannot join a Longshot game. The first start builds the game from your own copy (10 to 45 minutes); later updates put the new co-op into it in a few minutes, or build it again when Longshot or our game patches move (0.11.2 builds it again, once). If Longshot's server cannot be reached, the build takes the same files from our [mirror](https://github.com/daurosk/oot-remake-multiplayer/releases/tag/longshot-mirror-v3.0.0-rc.4), each checked by its SHA-256.

## Works (seen in two-game tests)

- **Hosting and joining in the game**: Host and Join in the **Multiplayer** tab (on the title screen press **−**), one invite code for the whole hosting session (**Join again** rejoins), **Leave**, joiners playing from the host's save, the self-updating start file, and **Same network or VPN** on the Host screen (one line with the address and the join password for friends in the same house or on a VPN, pasted into Join). Up to 16 players per session: tested with 2, more is experimental.
- **Joining and leaving**: joining, leaving and rejoining after a crash. A join password turns away a wrong or missing password, and an address that keeps guessing wrong is shut out for a minute ([#160](https://github.com/daurosk/oot-remake-multiplayer/issues/160)).
- **Chat and names**: the chat box (**T**, another key in Settings), the player list (hold **F6**), name tags, and chat notices when someone joins or opens a chest. The old co-op panel with distance and ping is for debugging only (F7).
- **Other players as Link**, child and adult ([#111](https://github.com/daurosk/oot-remake-multiplayer/issues/111)), following them live and copying their whole pose, with Navi beside them. New in 0.11.0: they move smoothly, on an even game-frame clock (the steady jitter and the choppy steps of 0.10.1 are gone; see Known issues for what is left). A player who joins later gets a Link for everyone already there. Their sword now shows in their hand (fixed for 0.11.0), and the slingshot no longer stays stuck out.
- **Customize Link** (new): the Multiplayer tab's **Customize Link** page gives the tunic and each part of the gear (shields, swords, boots, gauntlets) its own colour. Your own Link wears it when the menu closes, and the other players see it on your Link; it is saved for the next start ([puppet.md, The Link customizer](puppet.md#the-link-customizer)). The kit makes the puppet pack again by itself after this update (a few minutes, once).
- **Randomizer** (new): OOTRR is built in; turn it on in the Mods tab (**OoT Remake Randomizer**, **Settings**). In co-op the host's seed is everyone's: each guest's game builds it by itself ([mods.md, The randomizer](mods.md#the-randomizer)). A game with the randomizer on no longer stops while it loads.
- **Minimap**: the dungeon map no longer vanishes, and the other players show on it.
- **Time of day** (new on Longshot): the host's time of day is everyone's; a guest takes the host's time when the host's save loads ([#192](https://github.com/daurosk/oot-remake-multiplayer/issues/192), [time.md](time.md)).
- **Difficulty and helping up** (new): the difficulty follows the number of players or what the host sets, and a player at zero hearts can be helped up by another.
- **Items**: key items, bottles, songs and one-time pickups are shared; small keys, Gold Skulltula tokens and heart pieces add up across players. Rupees, ammo and health stay per player. A shared Slingshot or bomb bag comes with its ammo ([#128](https://github.com/daurosk/oot-remake-multiplayer/issues/128)). A player who joins late gets the items found before. Heart containers raise every player's maximum health ([#88](https://github.com/daurosk/oot-remake-multiplayer/issues/88)).
- **Cutscenes and the Threads of Time**: the other Link hidden during your cutscene and held during theirs; the Threads of Time open for every player and its steps shared ([#193](https://github.com/daurosk/oot-remake-multiplayer/issues/193)).
- **Saves: the host's save decides.** When the host loads a save, every game goes back to that save's progress. A guest who joins from the title screen gets the host's save copied into a co-op save folder; press **Continue** to load it yourself (the chat says when: "Host save loading, don't load a save.", then "Success, load any save.") ([#167](https://github.com/daurosk/oot-remake-multiplayer/issues/167)).
- **Dungeons**: switches, doors and cleared rooms are shared, and a switch another player set stays set when you load your save ([#129](https://github.com/daurosk/oot-remake-multiplayer/issues/129)). A chest another player opens shows open in your game.
- **Boss rooms**: when one player enters a boss room, the others are moved in and the intro starts together; a player who walks out during the fight is pulled back in.
- **Enemies**: their position, animation and life follow the player who owns them; the extra enemies for more players no longer stand on one spot. All the Deku Babas of the Deku Tree's first room show in both games ([#132](https://github.com/daurosk/oot-remake-multiplayer/issues/132)). Townspeople and animals move the same in every game. The Stalchildren in Hyrule Field are shared too ([#124](https://github.com/daurosk/oot-remake-multiplayer/issues/124)).
- **Crates and thrown rocks** break in every game.
- **Things a player makes**: Deku seeds and arrows in flight and Deku Nuts appear in the other games, and seeds and arrows stay where they hit. A bomb another player holds stays in their hands with its fuse blinking, and it explodes on every screen at once, held or thrown.
- **`/teleport <name>`** moves you next to another player, in the same area or another one (into a dungeon: see Known issues).
- **Voice chat** (proximity, [voice.md](voice.md)) is off until you turn it on in the co-op settings; on, it is open mic, and the Voice mode row switches to push to talk (hold **V**). Off, your microphone is never opened. The Microphone row under it chooses which microphone (Default: Longshot's Insert menu's); there is no Speaker row: the voices play through the game's own sound output.
- **PvP**, off unless the host sets `pvp = on` in `coop-options.ini` (or types `/pvp on`): sword hits hurt the other players, both ways.
- **Kit**: `collect-logs` masks addresses and your PC and user name; the updater adds every new `coop-options.ini` setting below your own lines; `Revert.bat` goes back to the version before the last update; a `coop.ini` with a setting it does not know no longer turns co-op off.
- **Mods**: the Mods tab, and a note in the chat when your mods differ from the host's (see Other notes).
- **Gohma's intro** (fixed for 0.11.2): after it every player gets control back and the door closes for everyone.
- **Joining by address** (new in 0.11.2, from bmitch87's PR #230): IP address, Port and Password rows in Join, and a Port row when you host.
- **Chinese** (new in 0.11.2, from cirnoice9's PR #231): the co-op tabs in Simplified and Traditional Chinese when the game is set to Chinese.

## Known issues

- **Fixed in code for 0.11.2, not yet checked in a game**: every player can hurt a boss, Gohma can be stunned, a boss dies once for everyone and drops one Heart Container; Mido moves aside after the Deku Tree (a stuck save is mended about 3 seconds after you load it in Kokiri Forest); the Spiritual Stones and Door of Time steps, Zora's waterfall and Ruto's Letter (it goes into your first empty bottle) work for players who were not there; the boss difficulty applied again (on Automatic, more boss life per player; else the host's choice) and the blue warp for guests; other one-way story blockers and area gates mended; small-key doors, the Dodongo's Cavern Lizalfos door, carrying Ruto and Jabu-Jabu's lifts in every game; smoother enemies on slow connections, and townspeople and enemies no longer handed back and forth between players; randomizer seeds with a settings string from OOTRR's website. Seen in our tests: the Gohma softlock, the shared ocarina, Zelda's Letter and the crash when a player takes out the Hookshot ([#232](https://github.com/daurosk/oot-remake-multiplayer/issues/232)). Tell us if one of them still goes wrong.
- **Adult Link's Customize preview** is a flat picture, while child Link's turns in 3D. Not fixed yet.
- **An invisible Lizalfos**: in Dodongo's Cavern one Lizalfos can be invisible on one player's screen. Not fixed yet.
- **Host crash under heavy memory use**: a host crashed twice in Zora's Domain while the PC was nearly out of memory. Not fixed; `collect-logs` now records memory use, so send us its zip if it happens to you.
- **Your name and your invite code are private** (fixed for 0.11.1): a new player gets a random name (like *Goron-4821*); change it in **Multiplayer**, **Settings**. An invite code holds your internet address and the join password: **share it in DMs only**, never in a public channel.
- **Deku Tree switches, platforms, ladder and torch**: a switch only works for the player who presses it. When another player presses the compass room's floor switch (or shoots the slingshot room's eye), the event and its cutscene play for you too, but the lifts (the ladder, the torch) move only in their game. Press the switch yourself: the lifts rise without a second cutscene. Or leave the dungeon and come back for the ladder ([#176](https://github.com/daurosk/oot-remake-multiplayer/issues/176), [#129](https://github.com/daurosk/oot-remake-multiplayer/issues/129)).
- **Gohma and other enemies go after one player only** ([#150](https://github.com/daurosk/oot-remake-multiplayer/issues/150)): the other players' Links are not seen by enemies yet. The part that lets them be seen is built, but it is switched off in this release because it crashed the game with customized gear and the slingshot.
- **Customize Link, partly**: the Hylian Shield's frame takes its colour, but the game's metal shading draws it much darker than the colour you pick (not changed for 0.11.0). The boots (child and adult, and on the other players' Links) and child Link's straps are fixed in code for 0.11.0 but not yet fully checked in a game: tell us if one of them stays in the game's colours. Your own Link's tunic is now all in your colour (it was only partly) and a player's colour is the same on every screen (seen in our two-game test with a pink tunic and a coloured shield). Tell us what you see.
- **Kakariko graveyard** (new, not yet seen in a two-player game): the Poe and the gravestones a player pushes are now shared. Tell us whether the Poe shows in both games at night and a pushed grave moves in both.
- **Slow walking and turning**: the other Link could wobble slightly (about 1 cm) while walking slowly and turn a little past where it stops; fixed in code for 0.11.0, being checked in our playtest.
- **Kakariko gate**: the gate step goes through the game's own quest steps, so the gate opens for every player; since 0.11.2 Zelda's Letter goes for everyone once it is open. Not yet played through in our tests; tell us if the gate stays shut for you ([#171](https://github.com/daurosk/oot-remake-multiplayer/issues/171)).
- **The randomizer**: if a guest's game cannot build the host's seed, that guest plays the base game; since 0.11.2 the chat says so to everyone. Do not install OOTRR by hand next to co-op (in `mods\`, or as a second copy of OOTRR 0.5.0): the game crashes at start; the kit's own is enough. A seed is built with the mods that are on at that time; turn other mods on or off before building. OOTRR's next release is due soon; a co-op update moves to it if it needs one.
- **Split screen is experimental**: it runs two full games on one PC with Nucleus Co-op, one per player (about 10 GB of RAM each and a strong graphics card; [play-lan.md](play-lan.md#split-screen-experimental)). Native split screen, one game for both ([local-coop.md](local-coop.md)), comes in a later release.
- **Another player's sword without its blade**: with 5 or more players, or with the Giant's Knife or the broken knife, another player's sword can still show without its blade (fix after 0.11.0).
- **Another player's ocarina is upside down** in their hand (fix after 0.11.0).
- **The ocarina**: the notes of other players' songs are built in, not yet heard in our tests ([#152](https://github.com/daurosk/oot-remake-multiplayer/issues/152)). Taking the Ocarina out holds the other players for about 4 seconds, and while a player plays, the other Link is sometimes held still or hidden for a moment as if in a cutscene ([#86](https://github.com/daurosk/oot-remake-multiplayer/issues/86)).
- **Microsoft Defender** may warn about the zip or `Update.bat` ("Trojan:Script/Wacatac"): a false alarm on our scripts, which we report to Microsoft.
- **Built in, not yet checked on Longshot**: Epona seen by everyone with more than one rider ([#199](https://github.com/daurosk/oot-remake-multiplayer/issues/199)), townspeople walking on every screen ([#200](https://github.com/daurosk/oot-remake-multiplayer/issues/200)), no black screen in another player's cutscene ([#173](https://github.com/daurosk/oot-remake-multiplayer/issues/173)); these worked on the emulator before.
- **Masks** reach the other games but have not been seen on the other Link's screen yet ([#91](https://github.com/daurosk/oot-remake-multiplayer/issues/91)). Tell us if you see them.
- **The other Links' sounds** are in the puppet pack, but our tests have no sound: tell us whether their footsteps, sword and voice can be heard ([#131](https://github.com/daurosk/oot-remake-multiplayer/issues/131)).
- **`/teleport` into a dungeon**: in a dungeon you are moved next to the other player only when they are in the room you arrive in; otherwise you stay at the entrance; type `/teleport` again there to be moved to their room (from inside the dungeon it goes to any room), or walk ([#197](https://github.com/daurosk/oot-remake-multiplayer/issues/197)). If you are frozen, close the game and start it again, and walk through the loading zones instead.
- **A locked dungeon door another player opened**: fixed in code for 0.11.2 (it opens for you too). If it still stays shut, type `/teleport <their name>` in the chat (inside a dungeon it takes you to them in any room), or step a few metres back from the door and come again.
- **Game version**: only version 1.1.1 of the game (build `e0f3ccfaf50065ae`) is supported; every player needs that one. A game it does not know is refused with a log line naming what differs ([#97](https://github.com/daurosk/oot-remake-multiplayer/issues/97), [game-builds.md](game-builds.md)).
- **Linux kit (experimental)**: the Linux and Steam Deck kit (`oot-coop-<version>-linux.zip`, [setup-linux.md](setup-linux.md)) is built by our CI with the same co-op, but has not been played on a real Linux PC or a Steam Deck in our tests yet; voice chat is not on Linux yet, and a relay join code works only in the Windows kit. 0.11.2 adds the host's save, pad choice, local pads and colours on Linux (StarAppeal's PR #228) and typing and pasting in the co-op text boxes; these are checked by our CI only ([#127](https://github.com/daurosk/oot-remake-multiplayer/issues/127)).

## Longshot

- The game is [Longshot](https://git.magicbean.dev/MagicBeanDev/Longshot), a native PC version that the kit builds on your PC from your own game ([setup.md](setup.md)).
- It needs Vulkan 1.3 with mesh shaders: NVIDIA RTX 20 or newer, AMD RX 6000 or newer; Intel is mostly untested.
- Longshot is young: it can crash in some places or on some cards. Its own open problems are on [Longshot's issues page](https://git.magicbean.dev/MagicBeanDev/Longshot/issues). If it also crashes with co-op off ([setup.md, If something goes wrong](setup.md#if-something-goes-wrong)), it is Longshot's problem, not co-op's.
- On speakers, open-mic voice chat can send some of the others' voices back as an echo (there is no echo cancellation): use headphones or push to talk. Not yet tested with people talking: tell us how it sounds.

## Low frame rate

- Longshot builds its shaders the first time it sees each place, so the first minutes in a new place may stutter; it is smooth the next time ([setup.md, Low frame rate](setup.md#low-frame-rate)).
- The co-op code reads the game at most every 33 ms, and its debug logging is off by default.

## Other notes

- **Mods**: every game tells the others which mods it runs; when yours differ from the host's, the chat says so and the Mods tab lists what differs. You can still play, but a mod that changes the world (items, chests, enemies) can make your games disagree ([mods.md, Mods in co-op](mods.md#mods-in-co-op)).
- Windows may warn about the kit's programs the first time (unsigned): **More info**, then **Run anyway**. Windows Firewall may ask to allow `coop_server.exe` (on the host) and the game: allow them on Private networks (and Public for Hamachi or Radmin VPN, [play-online.md](play-online.md)).
- Hosting: **Host** in the Multiplayer tab copies an invite code for friends over the internet ([play-online.md](play-online.md)). It asks api.ipify.org (HTTPS) for the internet address; `public_address_lookup = no` in `coop-options.ini` turns that off. If friends cannot connect, try a VPN or port forwarding ([play-online.md](play-online.md)).
- If a game is killed (not closed) and started again at once, joining takes a moment: the game asks again by itself for up to 12 seconds while the server lets the old one go.
